# Evidence

Every image below is a real Chromium render of the running app, produced by
`npm run evidence` (headless Chrome 155, this host). The script **fails** if a
capture does not match its own claim: wrong theme token, wrong layout id, wrong
viewport, non-zero console/page errors, or horizontal overflow. Filenames cannot
lie.

Regenerate:

```sh
npm run build && npm run serve &     # http://127.0.0.1:8123
npm run evidence                     # writes docs/evidence/* + manifest.json
```

`manifest.json` records, per file, the live `data-theme` / `data-layout` /
`data-quality` values, the viewport, byte size, and a SHA-256 prefix. Hashes are
of the committed PNGs; re-capture on a different GPU stack will legitimately
change them.

| `theme-oled-desktop-galaxy.png` | oled | desktop | 1280×800 | `30a1861f4312` |

OLED is verified programmatically, not by eye: the capture asserts
`document.documentElement.dataset.theme === 'oled'`, and `tests/interaction/themes.mjs`
additionally samples the canvas corner pixel and requires exactly `0,0,0`, with
`--bg`, `--bg-deep`, `--surface` and `--surface-2` all resolving to `#000000`.
Only small inset controls (`--surface-3`) are lifted, so regions remain visible
without lighting up large areas of the panel.
